# PostKit 0.1.0

This release moves PostKit into its own public workspace and establishes the
first stable package boundary for the component system.

:::postkit-callout{title="Release status" tone="tip"}
The package artifacts and clean-consumer checks are ready. Publication remains
guarded by the npm release workflow.
:::

## Added

- Chakra-backed components for prose, media, technical content, calls to
  action, publication structure, and social content.
- Framework adapters for Next.js, React Router, TanStack Router, and Astro.
- A typed Markdown component map and strict directive transformer.
- Independent `body`, `heading`, and `mono` font configuration.
- Deterministic tarball, clean-consumer, and registry preflight checks.

## Package lineup

| Package                    | Purpose                                                    |
| -------------------------- | ---------------------------------------------------------- |
| `@postkit/react`           | Core React components, theme recipes, and Markdown tooling |
| `@postkit/next`            | Next.js links and MDX component integration                |
| `@postkit/react-router`    | React Router link integration                              |
| `@postkit/tanstack-router` | TanStack Router link integration                           |
| `@postkit/astro`           | Astro components and React bridges                         |
| `@postkit/unfurl`          | Provider-neutral link metadata resolution                  |

## Markdown stays portable

PostKit directives contain literal, allowlisted props:

```md
:::postkit-callout{title="A portable note" tone="note"}
This content can move between PostKit renderers.
:::
```

Unknown or invalid component props fail the build by default, keeping authored
content aligned with the runtime component contract.
