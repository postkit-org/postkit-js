A callout is a small thing: a box, a word of warning, a tip. But the moment an article leaves the page it was written for, that box has to survive a feed reader, a newsletter and an editor’s preview pane[^renderers], each with different rules about what may run.

Postkit treats the callout as [content rather than markup](/docs/introduction). Install the renderer you want and the article comes along unchanged.

<Aside>
  Postkit grew out of Prismark’s need to render the same components in the
  editor and on the page.
</Aside>

<Terminal command="npm install @postkit/react" output="added 1 package in 2s" />

## Write the component once. A tag in MDX, a directive in Markdown, one definition behind both.

Both forms validate against the same definition, so a typo in a [tone](/components/callout) fails the build instead of the reader[^validation].

  filename="post.mdx"
  language="mdx"

</Callout>'

[^renderers]: Feed readers drop scripts and most styles, email clients drop more, and preview panes often render without the site’s CSS at all.

[^validation]: Directives are checked against the same schema as MDX props, and the error names the file and line.

[^contract]: The contract is the definition: props, parts and their data-postkit-part names. Views can change; those can’t.
