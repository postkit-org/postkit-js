Customizing

Part styles. Make every component match your brand without forking it.

Restyle any component, or any piece of one, with the CSS or theme you already have. Upgrades still land cleanly because you never touch the source.

Every rung keeps the component’s contract, so posts, validation and Prismark keep working however far you go. Part styles is the rung most sites stop at: the whole look, none of the maintenance.

Every part has a name

Every renderer stamps the same names on each part of a component, along with its state:

Rendered HTML
<aside data-postkit-component="Callout"
       data-postkit-part="root"
       data-tone="tip" data-variant="subtle">
  <span data-postkit-part="icon" aria-hidden="true"></span>
  <div data-postkit-part="content">
    <p data-postkit-part="title">Keep the content</p>
    <div data-postkit-part="body">…</div>
  </div>
</aside>

Each component page lists its parts. Style them once and they look the same in every post.

Headless: CSS

With the headless renderer, plain CSS is enough. Load it after styles.css, or leave the stylesheet out and start from bare parts.

site.css
[data-postkit-component="Callout"] {
  border-radius: 4px;
  border-left: 3px solid var(--brand);
}

[data-postkit-component="Callout"]
  [data-postkit-part="title"] {
  font-family: var(--font-display);
  letter-spacing: -0.01em;
}

[data-postkit-component="Callout"][data-tone="caution"] {
  --postkit-tone: var(--brand-red);
}

Headless: class names

Prefer utility classes? Pass them per part. They’re applied alongside the part names, so the two approaches mix.

lib/postkit.ts
export const postkit = createPostkit({
  kits: [article],
  overrides: {
    Callout: {
      classNames: {
        root: 'rounded-sm border-l-4 border-brand',
        title: 'font-display tracking-tight',
      },
    },
  },
})

Chakra: recipes

With @postkit/chakra, parts are slots in a recipe. Your system’s tokens flow straight through.

theme.ts
import { createPostkitTheme } from '@postkit/chakra'

export const postkitTheme = createPostkitTheme({
  callout: {
    base: {
      root: { borderRadius: 'l1', borderStartWidth: '3px' },
      title: { fontFamily: 'heading' },
    },
    variants: {
      tone: { caution: { root: { borderColor: 'red.solid' } } },
    },
  },
})

Scope it

Styles don’t have to be global. Scope them to a section of the site, like docs that need denser code blocks than the blog:

docs.css
.docs [data-postkit-component="CodeBlock"] {
  font-size: 13px;
  --postkit-code-line-height: 1.6;
}

When CSS isn’t enough

Swap a single part for your own with Defaults and slots, or replace the whole render with a view. Both keep the contract.
