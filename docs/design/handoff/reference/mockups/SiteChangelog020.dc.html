Changelog / 0.2.0

Postkit 0.2.0. Portable documents, host-native Chakra and email.

Postkit grows from a React component collection into a portable publishing system: content moves between HTML, Markdown, MDX and JSON, and renders on the web or in email.

This release expands Postkit from a React component collection into a portable publishing system. Content can now move through versioned HTML, Markdown, MDX and JSON representations, then render through React, framework adapters, Astro, or email-specific components.

!

Review before upgrading

Postkit remains pre-1.0, and this minor release contains deliberate component renames and visual-default changes. Upgrade related @postkit/* packages together and review the migration notes below.

Added

  • @postkit/core, with a versioned document model plus safe HTML, Markdown, MDX and JSON parsing and serialization.
  • DocumentRenderer and document-specific exports from @postkit/react/document.
  • @postkit/email, with email-safe components built on Chakra Email.
  • @postkit/shiki, with a lazy syntax-highlighting adapter for code blocks.
  • Controls for copying, wrapping, line numbers, titles, language metadata, highlighted lines and maximum code-block height.
  • Focused @postkit/react/theme and @postkit/react/remark entry points.
  • A generated component manifest and live component explorer covering variants, examples, renderer support and runtime requirements.

Changed

  • Component exports use generic names such as Callout, CodeBlock and AuthorCard. PostkitProvider keeps its branded name.
  • The React renderer is host-native by default: Chakra headings, links, lists, buttons, inputs, tables and tabs inherit your recipes and tokens.
  • Postkit’s standalone look is now opt-in through postkitDefaultTheme.
  • Code blocks default to no line numbers and no wrapping, scroll horizontally, and support inline or tooltip copy confirmation.
  • Chakra UI compatibility starts at 3.29.0 and stays below version 4.

Migrating from 0.1

Remove the Postkit prefix from component and component-prop imports:

post-layout.tsx
// 0.1
import { PostkitCallout, type PostkitCalloutProps } from '@postkit/react'

// 0.2
import { Callout, type CalloutProps } from '@postkit/react'

To keep the previous standalone look, opt into the preset:

article-providers.tsx
import { PostkitProvider, postkitDefaultTheme } from '@postkit/react'

export function ArticleProviders({ children }) {
  return (
    <PostkitProvider preset={postkitDefaultTheme}>{children}</PostkitProvider>
  )
}
